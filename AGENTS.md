## Commit Practices

Commit atomically and as often as possible. Each commit should represent a single, self-contained logical change that can stand on its own — easy to review, easy to revert, and easy to reason about in isolation.

Guidelines:
- One logical change per commit. Don't bundle unrelated edits.
- Commit early and commit often. Don't let work pile up into a mega-commit.
- Each commit should leave the repo in a working state where possible.
- Write commit messages that explain *why*, not just *what*.
